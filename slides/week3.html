Block 1 · Computational graphs

Any formula a program computes is a graph of simple operations

f(x, y) = (x + y) · y

inputsx = 2, y = 3
↓
a = x + ya = 5
↓
f = a · yf = 15
  • One node per operation, an edge from each input to its use.
  • Each node knows only its local derivatives: for a · y, they are y and a.
  • y is used twice: by the sum and by the product.
  • The forward pass evaluates nodes in an order where inputs come first.

Draw the graph on the board as a tree with y feeding two nodes. Ask what the order constraint is called: a topological order. The engine of week 4 builds this graph by itself as the code runs.

Block 1 · The chain rule, scalar

Along a chain, multiply the local derivatives

A chain

x → u = g(x) → f(u)
df/dx = f′(u) · g′(x)

Example: f = ln(1 + e^(2x)) at x = 0: u = 1 + e^(2x) = 2; df/du = 1/u = 0.5; du/dx = 2 e^(2x) = 2; so df/dx = 1.

Two paths: add

When an input reaches the output along several paths, the derivative is the sum over paths of the products along each. In (x + y) · y, y has two paths.

Do the example on the board, then the two-path rule on (x + y) y: df/dy = (path through the sum) a-adjoint times 1, plus (direct path) a. That gives y + a = 3 + 5 = 8, which matches the formula's derivative x + 2y = 8. Multiplying along a path and adding over paths is the whole of backpropagation.

Block 1 · A backward pass

Go down the graph once, passing adjoints to inputs

NodeValueLocal derivative to its inputsAdjoint ∂f/∂node
f = a · y15to a: y = 3; to y: a = 51
a = x + y5to x: 1; to y: 11 · 3 = 3

y31 · 5 + 3 · 1 = 8
Accumulate. y's adjoint is the sum of what each user sends it. Overwriting instead of adding is the classic engine bug.

Fill the last column row by row, top down. The adjoint of the output is 1. Every node multiplies its adjoint by its local derivative and sends the product to each input, which adds it to what it already has. Week 4's engine has a test for exactly this accumulation.

Block 2 · Forward mode

Forward mode carries one tangent up with the values

Pick one input direction. Each node computes its value and its tangent, d node / d input, from its inputs' tangents.

(x + y) · y, tangent along xValueTangent
x, y2, 31, 0
a = x + y51
f = a · y151 · 3 + 5 · 0 = 3

One pass, one direction

A forward pass gives the derivative of every output along one input direction: one column of the Jacobian. For the full gradient of f you need a pass per input.

Forward mode is easy to implement with dual numbers: each number carries a value and a tangent, and every operation updates both. Its cost per pass is a small multiple of the function's cost. The lab has one forward-mode step so participants feel the difference.

Block 2 · Which mode

Reverse mode wins when many inputs feed one output, as a loss does

FunctionForward passesBackward passes

The price of reverse mode. The backward pass needs every value of the forward pass, so they are kept in memory until it runs. Saved activations are why training needs more memory than prediction.

The backward pass costs a small constant multiple of the forward pass, independent of the number of weights. Memory is the trade: depth in SPC-DLR-302 (saved activations and memory). Frameworks use reverse mode for training and offer forward mode for the cases in the last row.
