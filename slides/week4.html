Block 1 · The chain rule with vectors

For vector functions, the chain rule multiplies Jacobians

Composition

J(F∘G)(x) = J_F(G(x)) · J_G(x)

Shapes chain like the maps: (m × k) · (k × n) = m × n. Matrix products as composition of maps, from FND-MTH-101.

A network is a long composition: L = ℓ(f₃(f₂(f₁(x)))).

Two orders of multiplying

Forward: start at the input, J₃ (J₂ (J₁ v)), one direction v at a time.
Reverse: start at the loss, ((gᵀ J₃) J₂) J₁, with gᵀ a row vector. Same product, very different cost.

The parenthesisation is the whole story of forward against reverse mode. Because L is a scalar, gᵀ is a single row, and each product in the reverse order is a vector times a matrix: never a matrix times a matrix.

Block 1 · What a backward pass passes

A layer never builds its Jacobian; it passes a vector-Jacobian product

OperationUpstream g = ∂L/∂ySends back
Sum, y = a + bgg to a, g to b
Elementwise, y = f(x)vector gg ⊙ f′(x)
Dot, y = w · xnumber gg x to w, g w to x
Matrix–vector, y = A xvector gto x: Aᵀg; to A: g xᵀ
Tensors. Reverse mode on whole arrays, with broadcasting, is the subject of SPC-DLR-302. This course stays with scalars and small vectors.

Derive Aᵀg on the board for a 2 by 3 A: each x_j reaches every y_i with local derivative A_ij, so its adjoint sums g_i A_ij over i. Problem set 4 asks for the A-side, so leave that row's derivation to them. The hand-over to SPC-DLR-302 is deliberate: tensor-level differentiation is not taught here.

Checkpoint 1

What shape is the weight gradient?

A layer computes y = A x with A of shape 3 × 5, then a scalar loss L follows. What shape is ∂L/∂A?

5
5 × 3
3 × 15
3 × 5
Why. L is a scalar, so ∂L/∂A has one entry per entry of A: the outer product g xᵀ is 3 × 5.

Answer: D. Rule worth repeating: the gradient of a scalar has the shape of the variable. A shape mismatch is the first thing to check when a backward pass crashes.

Block 2 · The engine's one idea

Each operation returns a node that knows how to pass its gradient back

def sqrt(self):
    s = math.sqrt(self.data)
    out = Value(s, (self,), "sqrt")

    def _backward():
        # local derivative 1 / (2 sqrt(x))
        self.grad += out.grad / (2 * s)
    out._backward = _backward
    return out
  • Value: the forward result, computed now.
  • Parents: the inputs, so the graph can be walked.
  • _backward: a closure that remembers what it needs (here s).
  • +=: a node may receive from several users.

The square root is not one of the lab's operations, on purpose: the lab asks for addition, multiplication, power, exp, log, tanh and ReLU. Every one of them has this same shape; only the value and the local derivative change. Point at the closure: _backward runs later, after the forward pass, and must not recompute anything it can remember.

Block 2 · Walking the graph

backward() visits nodes in reverse topological order

→
2 · Seedthe output's grad = 1

3 · Reversecall each node's _backward, last to first

Why the order

A node may pass its gradient on only after every user has sent its share. Reverse topological order guarantees it.

Why not recursion

A recursive sort fails on a chain deeper than Python's recursion limit (about 1,000). The test suite has a 5,000-node chain: use a loop and a stack.

Draw a diamond graph (a feeds b and c, both feed d) and show what goes wrong if a's _backward runs before c's: a passes on an incomplete gradient. Do not write the topological sort on the board: it is task 2. A depth-first search with an explicit stack and a "done" marker is the usual way.

Checkpoint 2

What goes wrong in this backward pass?

An engine calls every node's _backward in the order the nodes were created (inputs first), after setting the output's grad to 1. What do the inputs end with?

The correct gradients
Zero, or only part of their gradient
The correct gradients with flipped signs
An error about the graph's order
Why. Inputs run their _backward before their users have sent anything, so they pass on zeros; only the output's direct parents receive anything.

Answer: B. Silent wrong numbers, not a crash: the reason every engine needs a test suite and a referee.

Block 3 · Testing an engine

Two referees: finite differences and a framework's autograd

f64 = dict(dtype=torch.float64, requires_grad=True)
x = torch.tensor(0.5, **f64)
y = torch.tensor(-1.2, **f64)

f.backward()

Block 3 · What the suite tests

Ten tests, each aimed at one way an engine goes wrong

  • Values and gradients of +, ×, constants on either side
  • A reused node, and one node used twice in a product
  • Each unary operation against central differences
  • ReLU on both sides of zero
  • 20 random expressions, seeded
  • Your Lab 3.1 loss: the hand gradient again
  • A 5,000-node chain, and zero_grad

What goes wrong at a kink

ReLU has no derivative at 0. The engine must choose (0, here); a central difference straddling 0 returns 0.5. A "failed" check exactly at a kink is not a bug.

The suite is labs/engine_tests.py; read it with the room for a minute. The capstone runs the same suite on each participant's engine, and the oral check asks them to trace a backward pass through it: their code, their explanation.

Change ReLU's derivative to 0.5

Week 4 · wrap-up

Three things to keep

Vector-Jacobian products

Reverse mode multiplies from the loss end: a vector times each Jacobian, never a matrix product.

Node, closure, +=

Each operation records its inputs and a closure that adds its share of the gradient.

Two referees

Finite differences catch wrong formulas; a framework's autograd also catches small errors.
